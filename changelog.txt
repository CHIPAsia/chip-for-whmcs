== Changelog ==

## [1.7.4] - 2026-10-09

### Fixed
- Payment method whitelist: the DuitNow QR and Shopee Pay groups are now resolved against the **order amount** instead of a fixed RM 10. A method whose minimum exceeds the order total is resolved to its sibling variant (or out) correctly, and a method that only becomes available above RM 10 is no longer missed. The admin configuration screen keeps the safe default (RM 10), since it is not order-scoped.
- Payment method whitelist: a failed availability lookup (CHIP API error, timeout, network failure, or missing credentials) no longer silently **removes** the DuitNow QR / Shopee Pay group from the whitelist. The resolution now fails **OPEN** — the CHIP-preferred variant is emitted so the method stays payable. A genuine empty answer from CHIP still resolves correctly.
- The availability cache is now keyed per amount, so an answer resolved for one order total cannot be reused for a differently-priced order.

### Changed
- `ChipAPI::payment_methods()` accepts an optional `$amount` (sen) parameter, defaulting to 1000 for backwards compatibility.
- The API base URI is overridable via a `CHIP_API_BASE_URI` constant, so a test harness can point the client at a local stub. Production behaviour is unchanged.

## [1.7.3] - 2026-08-27

### Changed
- Renamed the "CHIP Crypto Coin" gateway to "CHIP Stablecoin" to match the product naming used across CHIP's public-facing materials. The internal gateway handle (`chip_crypto_coin`), the CHIP API payment method value (`crypto_coin`), and existing admin settings are unchanged — no reconfiguration is required on upgrade.

## [1.7.2] - 2026-08-03

### Changed
- Payment method whitelist: collapsed card networks (Visa, Mastercard, Maestro) into a single "Card" tickbox that expands to the three networks supported by the merchant's brand.
- Payment method whitelist: collapsed DuitNow QR variants into a single "DuitNow QR" tickbox. When the merchant's brand supports both `dnqr` and `duitnow_qr`, the emitted value is `dnqr`; otherwise the only supported value is emitted.
- Payment method whitelist: collapsed Shopee Pay variants into a single "Shopee Pay" tickbox. When the merchant's brand supports `shopee_pay`, that value is emitted; otherwise the fallback is `razer_shopeepay`.

### Removed
- "Update client information" admin toggle. The corresponding code path was removed in 1.7.1. Existing database rows with this setting are silently ignored.

### Validation
- "Disable Recurring Payments" and "Force Tokenization" cannot both be enabled on the same gateway. If both are ticked, the invoice page now shows a clear configuration error instead of silently saving a card at CHIP that WHMCS will not store.

### Migration notes
- Existing per-method whitelist keys (`payment_method_whitelist__visa`, `__mastercard`, `__maestro`, `__dnqr`, `__duitnow_qr`, `__razer_shopeepay`, `__shopee_pay`) saved in `tblpaymentgateways` from earlier versions are silently ignored. Re-tick the new group tickboxes (`__card`, `__duitnow_qr`, `__shopee_pay`) after upgrading to apply whitelisting.
